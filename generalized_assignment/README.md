# 一般化割当問題（GAP）ソルバ

**[generalized_assignment.hpp](generalized_assignment.hpp) 1ファイルだけで使える C++17 ヒューリスティック。** 標準ライブラリだけで利用できる。ファイル全体を提出コードへ貼り付けられる。

各仕事を必ず1つの担当先へ割り当て、担当先ごとの容量制約を満たしながら総費用を最小化する。消費資源量と費用は仕事・担当先の組合せに依存してよい。禁止割当、負の費用、ゼロ消費・ゼロ容量、整数、小数に対応する。仕事間の二次費用・複数種類の資源は扱わない。

## 使い始める

```cpp
#include "generalized_assignment.hpp"

// 行=仕事、列=担当先。担当先番号は0始まり。
cpopt::gap::Solver<> solver(
    {{1, 7}, {4, 2}, {3, 6}},  // cost[job][agent]
    {{2, 3}, {3, 2}, {2, 2}},  // resource[job][agent]
    {4, 4});                   // capacity[agent]

cpopt::gap::Options options;
options.time_limit = 1.8;      // このsolve()に使えるwall time（秒）
const auto& result = solver.solve(options);
if (result.feasible) {
    // result.assignment = {0, 1, 0}、result.objective = 6
}
```

`Solver<>` は `Solver<std::int64_t, std::int64_t>`。費用型と資源型を独立に指定できる。

```cpp
cpopt::gap::Solver<double> decimals(
    {{0.1, 0.7}, {0.4, 0.2}}, {{0.2, 0.3}, {0.3, 0.2}}, {0.4, 0.4});
cpopt::gap::Solver<std::int64_t, double> mixed(
    {{1, 7}, {4, 2}}, {{0.2, 0.3}, {0.3, 0.2}}, {0.4, 0.4});
```

最大化したい場合は費用の符号を反転して最小化し、結果の符号を戻す。最小整数値の符号反転はオーバーフローするため、入力範囲を確認する。

禁止割当は第4引数の `vector<vector<unsigned char>> allowed` で指定する。0は禁止、それ以外は許可。省略時は全組合せを許可する。ある仕事を固定するには、その仕事の許可先を1つだけにする。第5引数は `uint64_t seed`、既定値は1。

## 途中解・部分解・探索状態から再開する

```cpp
solver.set_start({0, -1, -1}); // -1は未割当。既に割り当てた仕事も探索で動く。
options.time_limit = 0.05;
const auto& first = solver.solve(options);

// 同じオブジェクトを再度呼ぶと、探索途中の状態から追加の50msを使う。
// 最良解、現在解、乱数、tabu履歴、罰則、価格、elite集合を維持する。
const auto& second = solver.solve(options);

// 別オブジェクトでは割当配列をwarm startとして渡せる。
// 実行可能解、容量超過を含む解、-1を含む部分解のどれでもよい。
other_solver.set_start(second.assignment);

// 最良解ではなく、時間切れ時の実際の探索位置を取り出すこともできる。
auto partial = solver.current_assignment();
other_solver.set_start(partial);

// 全探索状態のインメモリ複製。問題データもコピーするので時間・メモリに注意。
auto checkpoint = solver;
```

`set_start()` は新しい開始点に置き換え、保存最良解・tabu・elite集合をリセットする。乱数、学習した罰則・価格、累積カウンタは維持する。完全な初期化には新しい `Solver` を作る。開始点の容量違反は受け入れるが、不正な番号や禁止割当は例外とする。開始点の検証・集計は `set_start()` 内で済ませるため、`time_limit=0` でも検証済み開始点を返せる。

`solve()` と `best()` はソルバ所有の `const Result&` を返す。次回の呼出しや `set_start()` により内容が更新される。過去の結果を保持するには `auto saved = solver.best();` とコピーする。割当配列を保存し、`set_start()` で再投入することもできる。

## 時間制限

`std::chrono::steady_clock` による実経過時間を使う。初期解補完、移動・交換の走査、連鎖、価格更新、部分問題の分枝限定、path relinking、最良解の検証・保存を同じ期限で打ち切る。主要な長いループは最大64回の確認呼出しごとに時計を読み、反復の境界でも確認する。

実際の探索期限は指定秒数から `max(safety_margin, min(2ms, 指定秒数×1%))` を引いた時刻。既定の `safety_margin` は0.2ms。余裕より短い予算では探索しない。

```cpp
const auto deadline = std::chrono::steady_clock::now() + std::chrono::milliseconds(1800);
// 他の処理を行った後、同じ絶対期限を使う。
const auto& r = solver.solve_until(deadline);
```

`solve_until(deadline, options)` は残り時間を計算して `options.time_limit` を置き換える。それ以外の設定は維持する。

**計測の対象は `solve()` 内。** コンストラクタは行列のコピー・入力検証・候補の前処理・メモリ確保を行い、時間制限の対象外。`set_start()`、`evaluate()`、ソルバや結果の利用者側コピーも対象外。提出全体の予算ではこれらの時間を含めて余裕を取る。一般OSのスケジューリング停止、ページフォルト、最大2,048要素のソート、ロールバックへの割込みまでは保証できず、hard real-time の上限保証ではない。

極端に短い予算では実行可能解が見つからないことがある。最良解を新しく保存できなかった場合は以前の検証済み結果を返し、補完途中の状態は `current_assignment()` と同じオブジェクト内に残す。以降の呼出しで補完を続けられる。

## 結果と終了理由

| メンバー | 意味 |
| --- | --- |
| `assignment` | 仕事ごとの担当先番号。未割当は−1 |
| `loads` | 担当先ごとの消費資源量 |
| `objective` | 割当済み仕事の費用合計。実行可能性は別に確認 |
| `unassigned` | 未割当仕事数 |
| `violation` | 許容誤差を超えた容量超過量の総和。元の資源単位 |
| `feasible` | 完全割当かつ容量制約を満たすか |
| `elapsed` | 今回の `solve()` 内の秒数 |
| `iterations` | 通常探索で採用した移動の累積回数。修復・PR・再構築は含まない |
| `moves_evaluated` | shift・swap・chain の評価候補の累積数。全処理量を示す値ではない |
| `restarts` | 再出発の累積回数 |

実行可能解が一度得られたら、同じオブジェクトの通常の継続で返却最良費用は悪化しない。まだなければ、未割当数、容量超過量、費用の辞書順で良い検証済み状態を保存する。`objective` の小ささだけを見て、不完全解や容量違反解を採用してはいけない。

| `reason` | 意味 |
| --- | --- |
| `TimeLimit` | 余裕時間を含めた探索期限に到達 |
| `IterationLimit` | 今回の反復数上限に到達 |
| `NoMoves` | 使用可能な移動がない（空問題や割当先が固定された問題など） |
| `ImpossibleJob` | 単独でも入る許可先がない仕事を前処理で検出 |

ヒューリスティックなので最適性は証明しない。`feasible=false` や `NoMoves` を、一般の実行不可能性の証明として扱わない。`ImpossibleJob` はその特殊な理由を検出した場合だけ返す。小数では許容誤差を含めた判定となる。

`solver.evaluate(assignment)` は探索状態とは独立に費用・負荷を再計算する。入力サイズ・番号・禁止割当も検証する。これは予算外の検証関数。

## 数値と入力範囲

整数の費用・負荷・差分には `int64_t` を使い、小数の探索と丸めて混ぜない。オーバーフローを避けるため、`B = INT64_MAX/8` として以下をコンストラクタで要求する。

- 費用が整数: `sum_job max_agent abs(cost[job][agent]) <= B`。
- 資源が整数: 各担当先の容量と、全仕事のその担当先への消費量合計がそれぞれ `B` 以下。

禁止された組合せも入力範囲の検査対象。超過時は `overflow_error` とする。探索の優先順位・罰則は浮動小数点だが、整数の結果費用と実行可能性判定は上記範囲内で厳密。

小数の集計は `long double` を使う（環境によって `double` と同精度）。資源の判定は

```text
load[i] <= capacity[i] + absolute + relative * capacity[i]
```

に相当する差分式で行い、既定値は `absolute=1e-10`, `relative=1e-12`。許容値はコンストラクタ第6引数 `cpopt::gap::Tolerance{absolute, relative}` で変えられる。整数資源にこの許容値は適用しない。費用の改善比較にはこの許容値を使わない。

小数では保存前に元の割当から必ず集計し直し、探索中も定期的に再集計する。ただし、極端に桁の離れた入力に対する数値保証や厳密な有理数演算ではない。`NaN`、無限大、負資源・負容量、不整合な行列、負の時間などは拒否する。ゼロ仕事は実行可能な空解となる。

## 探索の構成と計算量

容量超過に罰則を加えた評価値を使い、仕事の移動・交換を行う tabu 探索を基本とする。複数の仕事を連鎖的に動かす探索や、2〜4担当先の部分再配置を組み合わせる。停滞時には保存した良い解を使って再出発する。

担当先の容量の余裕を価格として評価し、初期解の構築や移動候補の選択に利用する。価格は初期化後も学習し、同じソルバへの次回の呼出しに引き継ぐ。価格学習にも時間予算を使うため、通常探索の反復上限が同じでも、時間予算によって探索経路が変わる場合がある。

仕事数を `n`、担当先数を `m`、仕事あたりの交換候補数を `k` とする。

- メモリは `O(n*m+n+m)` に加え、部分再配置用の固定長バッファを使用する。
- コンストラクタは行列のコピーと入力検証のほか、担当先ごとの資源量順ソートに `O(m*n*log(n))` を使う。
- 通常の移動・交換の走査は最悪 `O(n*m+n*k)`。160仕事以下では全交換を調べるため `O(n²)` の項が加わる。
- 256仕事以上では、仕事ごとの最良移動をキャッシュする。負荷が変わる担当先が少なければ再計算を減らせるが、全更新には `O(n*m)` かかる。

連鎖探索と部分再配置は、候補数・探索深さ・作業予算・時間で制限する。このため、近傍内の最適性も保証しない。

## 調整項目

| `Options` | 既定値 | 意味 |
| --- | ---: | --- |
| `time_limit` | 1.0 | 呼出しごとの秒数。有限・非負 |
| `iteration_limit` | `UINT64_MAX` | 呼出しごとの通常探索の反復上限。再構築や部分問題のノード数とは別 |
| `safety_margin` | 0.0002 | 期限前に残す最小秒数 |
| `swap_candidates` | 12 | 大規模時の仕事あたりswap候補。0で無効 |
| `chain_trials` | 64 | 連鎖探索を行うときの始点数。0で無効 |
| `chain_depth` | 12 | 連鎖に含む仕事数の上限。0〜16 |
| `repair_nodes` | 8192 | 制限再割当の作業予算。分枝限定ではノード数、2担当先の半分全列挙では両半分の列挙状態数。0で無効 |
| `path_relinking` | true | 再出発でeliteを使う |
| `restarts` | true | 停滞時の再出発 |
| `initial_prices` | true | 最初の構築前に上界不要の価格初期化を行う |
| `incremental_shifts` | true | 256仕事以上でstrict tabuのshiftキャッシュを使う。falseで全走査 |
| `double_shift_trials` | 64 | 8反復ごとの二仕事移動で調べる始点数。0で無効 |

同じseedでも、経過時間による価格学習の切上げ・探索の打切りにより結果は変わり得る。学習反復数も通常探索反復数も一致する場合は、同じ環境で探索経路を再現できる。同じオブジェクトの同時呼出しは非対応。
