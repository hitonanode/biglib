# 重み付き集合被覆・集合分割ソルバ

[set_cover_partition.hpp](set_cover_partition.hpp) だけで使える C++17・標準ライブラリのみのヒューリスティックソルバ。数百要素・数千〜数万候補集合、10 ms〜2秒程度を主対象とする。

- **集合被覆**: 全要素を1回以上覆い、選択集合の費用合計を最小化。
- **集合分割**: 全要素をちょうど1回ずつ覆い、費用合計を最小化。
- 負費用、小数、空集合、同じ要素集合を持つ複数候補に対応。
- 完全解・未被覆や重複のある不完全解から開始でき、内部状態を保持する継続実行にも対応。

最適解や実行可能解の発見を保証するソルバではない。特に集合分割は、実行可能性の判定自体が難しい。利用時は `result.feasible` を確認する。

## 使い方

```cpp
#include "set_cover_partition.hpp"
using namespace set_cover_partition;

Model p(4, Mode::Cover);       // 要素 ID は 0,1,2,3
p.add_set(3, {0, 1});          // 集合 ID 0
p.add_set(3, {2, 3});          // 集合 ID 1
p.add_set(1, {0, 2});          // 集合 ID 2
p.add_set(1, {1, 3});          // 集合 ID 3
Options o;
o.time_limit = 0.01;          // 秒。10 ms
o.seed = 42;
auto r = solve(p, o);
if (r.feasible) {
    // r.selected: 選択集合 ID の配列。この例なら {2,3}、r.cost == 2。
}
```

集合分割ではモデル生成時に `Mode::Partition` を指定する。集合の要素は順不同でよいが、同じ集合内の重複、範囲外 ID、非有限費用、合計絶対値が内部安全範囲を超える費用は例外。集合 ID は追加順で、縮約後も返却 ID は元の入力に対応する。

[標準入出力の例](solve.cpp): 先頭に `cover|partition 要素数 集合数 秒数`、続いて各集合の `費用 要素数 要素ID...` を渡す。任意の末尾行で `初期選択数 集合ID...` も指定できる。

```sh
c++ -std=c++17 -O3 set_cover_partition/solve.cpp -o /tmp/set_cover_partition
```

## 途中解・不完全解から再開

```cpp
o.initial_sets = {0};         // 未被覆を許す。分割では重複被覆も許す。
o.time_limit = 0.02;
auto first = solve(p, o);
o.initial_sets = first.selected;
o.time_limit = 0.05;
auto second = solve(p, o);
```

`initial_sets` は集合 ID の配列で、0/1フラグ配列ではない。ID の重複と範囲外は例外。初期選択は固定制約ではなく、探索中に取り除くこともある。初期解が実行可能なら、それより費用の大きい解を返さない。不完全解の場合は、まず制約違反の合計を減らし、違反が同じなら費用を比較する。

何度も短時間を追加する場合はこちらを使う。

```cpp
Options settings;
settings.initial_sets = {0};
settings.seed = 42;
Solver solver(p, settings);
auto a = solver.run(0.01);
auto b = solver.run(0.02);    // さらに20 ms。これまでの最良解を保持。
auto c = solver.run(0.1);
```

乱数状態、被覆数、差分評価、適応罰則、双対価格、候補走査位置、未完了の交換更新、残余探索の DFS スタックを保持する。被覆専用探索の gain/loss・行重み・禁止期間、分割の排出探索の途中状態も保持する。初期化や貪欲走査の途中で止めても、その場所から進む。`Solver` のコピーも独立した探索状態の複製になる。プロセスをまたぐ再開には `selected` を保存して `initial_sets` に戻す。

**モデルは Solver より長く生存させ、探索中は変更しない。** Solver はモデルを参照し、全入力をコピーしない。`add_set` による変更後の `run` は例外。モデル自体の代入・移動・破棄も、Solver がある間は行わない。

## 時間予算と停止

`solve(p, o)` は Solver の生成前から、`solver.run(seconds)` は呼び出し開始から `steady_clock` で壁時計時間を測る。探索用初期化、局所探索、価格更新、残余探索を同じ期限内で進める。`Options::deadline` を指定した場合は相対時間との早い方を使用する。保存された絶対期限は以後の `run` にも適用される。

既定で最大0.5 ms、かつ残り予算の5%以内を返却用に確保する。長い走査・差分更新・DFS に期限検査を入れ、中断途中の不整合な状態は結果へ出さない。時間切れでも、既に保存済みの最良実行可能解、または最良不完全解を返す。

`Model` の構築・入力の読み込みは予算外。Solver 作成時のメモリ確保、初期選択の検証、結果コピー、メモリ解放、OS による停止は強制中断できないため、**ハードリアルタイム保証ではない**。ゼロ秒・過去の期限でも初期選択の検証と結果作成は行い、空から完全解を必ず作る契約ではない。巨大で密な初期選択を渡す場合は、事前に `Solver` を作り `run` に予算を与えると初期検証を切り離せる。

`iteration_limit` は **各 run 呼び出し**の探索反復上限（初期構築の追加、被覆専用探索の反転・進めない場合の試行、分割の排出交換などを含む）。時間と併用でき、無限時間と有限反復なら再現可能な検査に使える。残余探索ノードや双対更新はこの反復数に含めず、それぞれ専用の上限も持つ。異なる探索方式の反復数は同じ仕事量ではない。`stats` の反復・ノード等は呼び出し間で累積し、`stats.elapsed` のみ当該呼び出しの秒数。

## 結果の意味

| フィールド | 意味 |
|---|---|
| `selected` | 選択した元の集合 ID。実行可能性は別フィールドで確認 |
| `coverage[i]` | 要素 i が何回覆われるか |
| `cost` | 返した選択集合の元の費用合計。不完全解でも定義される |
| `uncovered` | 一度も覆われていない要素の数 |
| `violation` | 被覆: 未被覆数。分割: 未被覆数 + `sum(max(coverage[i]-1,0))` |
| `feasible` | `violation == 0` |
| `lower_bound` | 全列で計算した Lagrangian 緩和値。未計算なら負の無限大 |
| `reason` | 時間、反復上限、候補ゼロの要素の検出、空の台集合で終了、のいずれか |

`NoCoveringSet` は一つも候補集合を持たない要素がある場合だけ。集合分割で「全要素に候補はあるが組合せが存在しない」場合を、時間切れだけで不可能と断定しない。`Exhausted` は空の台集合に対する終了であり、一般問題の最適性証明ではない。

費用合計の型は `long double`、探索評価はスケーリングした `double`。整数入力も浮動小数点で扱い、巨大な整数の1差や極端な桁差の厳密計算は保証しない。`lower_bound` は丸め誤差の余裕を引いた数値的な緩和値で、厳密な証明書ではない。`p.evaluate(selected)` で任意の選択を元モデル上で検査できる。

## 探索の構成と調整

同じ要素を持つ候補集合は最安のものへ縮約し、集合被覆では負費用の集合を採用して探索を始める。空の負費用集合は集合分割でも採用する。

集合被覆では、未被覆要素を覆う集合の追加と、選択集合の削除・交換を行う。集合分割では、不足・超過に適応罰則を加えた局所探索と、衝突する集合を外しながら未被覆要素を埋める排出探索を組み合わせる。双対価格による下界計算と、小さい残余問題の探索も行う。

| オプション | 既定値 | 用途 |
|---|---:|---|
| `fast_cover` | true | 被覆専用の行起点探索。falseなら汎用探索 |
| `cover_cost_bound` | true | 被覆専用経路の費用上限を使う4モード。falseなら2削除・再被覆の反復 |
| `incremental_penalties` | true | 分割・汎用被覆経路で罰則変更を差分更新 |
| `ejection_moves` | 256 | 分割の排出探索1バッチの手数。0で無効化 |
| `swap_origins` | 16 | 1回の交換走査で調べる削除側集合数。0で交換を無効化 |
| `composite_moves` | true | 有望な2交換を合併した3〜4列交換 |
| `adaptive_penalties` | true | incumbent に応じた罰則の縮小・増加 |
| `priced_restarts` | true | 被覆の再構築に双対 reduced cost を利用 |
| `repair_interval` | 64 | 残余探索を試みる局所探索反復間隔。0で無効化 |
| `repair_nodes` | 1500 | 1回の残余探索のノード予算。途中停止をまたいで消費 |
| `repair_columns_per_row` | 64 | 残余探索の各行の価格候補数。元の除去集合も保つ。0なら全候補 |
| `repair_max_remove` | 32 | pivot による破壊の集合数上限。小規模全体探索は対象外 |
| `dual_iterations` | 128 | 双対更新の総上限。被覆専用経路は `双対回数×2048 <= cover_cycles`。分割・汎用被覆経路は初解前最大32回、初解後は `双対回数×16 <= 累積反復数`。0で無効化 |
| `safety_margin` | 0.0005 | 秒単位の返却用余裕 |

`swap_origins`、`composite_moves`、`adaptive_penalties`、`repair_*` は分割・汎用被覆経路で使う。`priced_restarts` は汎用被覆経路だけに作用する。被覆専用経路はこれらの残余探索・価格付き再構築を実行しない。

価格更新の条件は累積カウンタを使い、厳密な各pass間の固定間隔ではない。各passは期限検査で中断できる。`cover_cycles` は被覆の破壊開始・未被覆行の提案回数、`ejection_steps` / `ejection_batches` / `ejection_improvements` は分割の排出探索の試行手数・開始回数・改善回数を記録する。

メモリは入力 incidence と各集合の `ceil(要素数/64)` 語の bitset、要素数・集合数に比例する作業配列が中心。
